# Lime 输入法 benchmark

评测衡量给定真实上文与当前词拼音时，LLM 排序第一候选是否严格等于原文词。只评候选重排，不让模型生成或改写目标。

## 语料与复现

旧的 48 个人工例子已移除。固定包含两类语料：

- `zhihu`：指定的 `rime-schema-compare/data/corpus/zhihu_hotlist_2026-08-30.txt` 完整快照，按 30 个问答块分开。原文件保留；仅将每块的来源链接头作为元数据排除，正文包含 61,921 个汉字。
- `classics`：鲁迅、朱自清、郁达夫的 13 篇经典文章，正文共 76,625 个汉字，超过知乎正文体量。逐篇保存来源与文本哈希。

冻结原文、分词边界、拼音和来源位于 `crates/lime-benchmark/data/`。生成步骤、固定版本和逐篇来源见该目录的说明及 `tools/prepare-benchmark-corpus.py`。运行评测不联网，不安装分词依赖。语料指纹涵盖冻结数据而非某一配置截取后的重复前文，因此整批结果可以共享同一指纹。

分词只在生成数据时完成。运行时按冻结边界流式展开，不把所有长前文复制到内存或 IPC。`builtin_dataset()` 保留离线 crate 的便捷 API，默认展开最多 128 字前文；`builtin_dataset_with_context_limit` 可显式指定 1–4096 字；服务使用 `visit_builtin_cases` 流式遍历。

## 逐词评测

1. 对每个知乎问答块或完整文章独立分词，跳过其第一个中文词。
2. 后续每个中文词都进入分母。混合词按中文与非中文片段拆分；字母、数字、标点、空白不作为预测目标，但逐字保留在上文中。
3. 上文来自同一文档中目标前面的原文，取末尾 `preceding_text_char_limit` 个 Unicode 字符；不包含当前目标和后文，也不把错误预测写回上文。文档开始处实际前文可能短于配置上限。
4. 全拼连接无声调音节，后续音节以 `a/e/o` 开头时加撇号；首拼取各音节的首字母，`ü` 用 `v`。每种模式单独生成结果行，不能混合成一个准确率。
5. 从相同 Rime 快照选取当前配置前 N 个候选，执行与日常输入路径相同的完整输入覆盖检查、候选过滤与 LLM 排序。
6. 严格比较 LLM 第一候选的 commit text 与目标词。未召回目标、无预测和推理错误均计为未命中，不从分母剔除，不以 Rime 首候选冒充 LLM 预测。

知乎为 35,767 个目标，经典文章为 49,798 个目标；每个组合共评测 85,565 个词。总准确率为两类命中数之和除以两类目标数之和，**不是**两列准确率的算术平均。

## 批量模型与配置

管理窗口选择已保存的多个模型、多行配置与全拼/首拼，服务评测其笛卡尔积，重复项自动去重，一次最多 32 个组合。每个组合始终包含全部语料。

可批量改变的参数为：

- `llm_rerank_count`：LLM 重排输入候选词数，1–128。
- `preceding_text_char_limit`：前文实际获取字符数上限，1–4096。

其他参数并非全部无关。拼音模式、模型与量化、Rime 方案/词库、Emoji 过滤、推理次数上限、模型 token 容量均可能改变 top1；字符上限也不等于 token 上限，模型仍可能截短较长前文。后端和运行版本会影响性能及数值结果。整批固定开始时的这些配置并在每行记录完整配置、实际加载模型 SHA-256；比较不同批次时必须核对它们。

每页展示数、前文预览长度不影响 LLM top1。采纳候选数为正时不改变 LLM 第一候选，评测统一使用采纳数 1、展示数 1、预览长度 0，不修改日常设置。

服务先缓存所有不同拼音的候选池，取整批最大候选数，再供各组合使用。生成快照期间若 Rime 方案或用户词库变化则整批失败，避免半旧半新；快照完成后日常设置变化不会改变该批输入。`rime_snapshot_sha256` 标识实际候选池和完整输入覆盖信息。评测模型独立加载，与当前日常模型可同时占用内存；载入失败仅使对应行失败，继续其余组合。相邻组合加载条件相同时复用模型。

## 结果、停止与隐私

结果表每个（模型、候选数、前文字数、拼音模式）一行，显示总准确率和两类语料准确率，完整结果按总准确率降序排列。没有完成数、正确数等统计列；运行进度用百分比。点击行可查看每类最多 8 个错误样例，包括实际使用的上文、拼音、目标与 LLM 首位结果。样例限制只影响展示和传输，不限制评分覆盖。

停止会保留已完整完成的结果行，正在运行的行保留有限错误样例但 `complete=false`，所有准确率为 `null`；未开始的行标记已停止。模型加载与单次推理不能中途打断，停止在其返回后生效。失败或未完成的行没有可排名的分数。

JSON 导出包含全部结果、完整配置、语料/候选池/模型指纹和有限错误样例。语料目录接口只传元数据；最多 32 行、每类 8 个错误样例可控制状态响应在 IPC 的 16 MiB 帧限制内。评测不学习、不写输入历史、不上传文本，不自动持久化报告；常规日志仍不保存语料内容。

## 局限与验证

自动分词和词级拼音可能存在多音字、专名或词边界错误；冻结数据保证复现，不代表人工语言学标注。模型可能在预训练中见过经典文章，两类语料不能代表全部实际输入场景；这里测的是原文逐词、正确历史上下文下的 top1，不衡量用户纠错、延迟分布或双拼。

```powershell
cargo test -p lime-benchmark -p lime-protocol -p lime-core
cargo fmt --all -- --check
powershell.exe -Command "npm run build --prefix crates/lime-management"
node --test crates/lime-management/src/ui/benchmark.test.mjs
```

独立 crate 的 `build_report` 仍支持完整观察值验证；服务使用流式计数器，并以相同观察值和完整报告交叉验证汇总结果。测试包含混合文本上下文、首词跳过、全目标覆盖、分母与加权总分、矩阵去重、非法配置、取消后的不可排名性及最大状态响应大小。
