# UI 与 Design Tokens

## UI 分工

### Windows 原生候选窗口

由 TSF C++ 适配层负责状态和交互，只使用固定版本的 WeaselUI 绘制，不保留第二套内置候选窗口。TSF 组合串由宿主文本控件以未确认文本渲染；候选窗只显示候选、分页状态和可选的前文预览，不再重复绘制拼音行。前文预览默认显示最近 32 个字符，可设置修改或关闭。

候选项只显示必要信息：候选文本、平台生成的编号和可选的紧凑前文预览。不显示排序分数、延迟、模型名称或内部状态。PageUp/PageDown 以及 Rime 默认的未移位 `-`/`=` 可翻页，滚轮由 WeaselUI 转发到同一状态机。

中文/英文模式遵循内置 Rime `ascii_composer`：左 Shift 无修饰短按切换，切换前提交未确认组合串；右 Shift 为 no-op，Shift+Space 不切换。英文模式不建立 TSF composition，字母、数字和半角符号由宿主键盘布局直接提交；中文模式继续显示候选，使用内置 Rime `half_shape` 标点的首选映射，无组合串和候选时的空格透传给宿主，有候选或组合串时由 TSF 处理；紧随无修饰数字后的句号保持半角 `.`（该规则只依赖上一按键，不读取光标前文；其他按键会重置），成对引号按焦点和模式边界重置。F1–F12 等功能键不属于 Lime 输入按键，透传给宿主。

无拼音组合串时的独立标点（空格除外）仍通过一个立即结束的 TSF composition 提交；无组合串和候选时的独立空格透传宿主，以便视频播放器等宿主继续响应播放/暂停快捷键；有候选或组合串时 Space 选择候选或提交组合，keydown/keyup 成对消费。按键回调不直接修改宿主 selection，避免 Chromium/WebView2 文本上下文在 `ITfInsertAtSelection` 中重入 Windows 文本输入框架。

候选窗口使用独立的 Win32 UI 线程和消息循环，不依赖宿主程序（包括记事本、QQ）的 TSF 回调线程绘制。窗口采用 Weasel 的每监视器 DPI、圆角、选中态高亮、编号列和状态提示；服务不可用时才进入“英文透传”，服务可用但 Rime 返回空候选时保留未确认组合串并隐藏候选窗口，等待 Enter 或 Space 提交原始拼音。

`OnTestKeyDown` 只做不进入 edit session 的上下文门禁和按键归属判断；它读取当前焦点、Weasel 的禁用/空上下文 compartments、只读状态以及 composition 能力，但不访问 IPC。候选读取和写入组合串在 `OnKeyDown` 的 edit session 中完成，避免宿主在 probe 回调期间持有锁而造成 `TF_E_LOCKED`。

MPC-BE 主窗口及其直接子播放视图获得原生键盘焦点时，即使 Windows 提供了可写的默认 IME context，也直接透传字母、标点、Shift 等按键，清理遗留组合状态，并保留当前中英文模式。此兼容规则仅匹配播放区域，文件名、搜索等编辑控件继续正常输入中文；独立的独占全屏窗口暂不在匹配范围内。不以临时 context 或缺少系统 caret 作为通用的非输入框判断。

TSF 写入组合串时以 `RequestEditSession` 的 `phrSession` 结果为准，使用 `TF_ES_READWRITE` 的 ASYNCDONTCARE 调度。`StartComposition` 的 `S_OK` 不代表一定创建了组合，必须同时检查 `ppComposition`；宿主拒绝时显示明确诊断而不是静默透传。取消会先清空组合范围再结束组合，并把 selection 折叠到组合末端；未完成的异步取消会继续吞键，避免 Esc 或后续字母泄漏到宿主。

新增拼音被只读上下文以 `TF_E_READONLY` 拒绝时，丢弃本次新增字符，继续消费按键并显示只读提示；此前有效的拼音保留，下一次可编辑输入不携带被丢弃的字符。焦点门禁已确认 context 不可用，或出现断开、无 selection、宿主拒绝 composition 等不可用 context 错误时，清空本地组合状态并透传当前按键，避免失焦后的输入在新编辑器中回放；已有有效 composition 遇单独的暂时性 `E_FAIL` 仍保留可重试状态。回滚必须尊重请求期间的焦点清理，不得恢复已清空的输入状态。

### Tauri 管理窗口

使用 Tauri 2、Vite、React、TypeScript、Tailwind CSS 4 和 shadcn/ui。前端只通过既有 Tauri commands 访问 Rust 服务，配置、模型预设和词库仍由服务持久化；主题沿用本地 `lime.management.theme` 偏好。没有独立诊断页，也不参与实时输入候选替换。

导航为设置、测试、评测、词库、历史，模型管理合并到设置。默认窗口 1040×760，最小 420×480；768px 以下切为顶部五项紧凑导航，以上使用固定侧栏。内容区最大 76rem；设置页根据内容区可用宽度自动分栏：能容纳两列各 28rem 加列间距时，左列为设置，右列依次为占用表格、模型选择，两列均分宽度；空间不足时按设置、占用表格、模型选择单列排列，DOM 和键盘顺序与之相同。表单自身宽度达到 40rem 时，相关数值字段并排显示，避免按窗口宽度把窄列中的控件挤在一起。两列随页面正常滚动，不设窄侧栏或额外的纵向滚动区域。表格仅在内容确实超出可用宽度时提供横向滚动；详情弹窗限制为视口高度的 90% 并独立滚动。

所有页面只显示必要字段标签、操作、数据与状态，不放说明性标题、分组标题、条目副标题或解释性段落。选中导航作为当前位置指示，无重复页面大标题。错误与不可撤销操作确认允许简短的行动说明。服务状态位于页头，刷新按钮可重试连接。

- 设置：模型列表、推理设备、重排与采纳候选数、Token 和推理次数上限、Emoji 开关、前文长度、输入方案与候选数集中在一页。单一保存按钮，未保存草稿可撤销；前文预览长度和采纳候选数执行跨字段校验。已有模型时修改后端、Token 上限、重排范围或推理次数上限会重载当前模型并刷新占用数据；Emoji 开关不触发重载。切换模型不覆盖未保存的设置。主题立即应用，支持跟随系统、浅色、深色。
- 模型操作：设置页内以紧凑列表显示名称和加载操作。添加、重命名使用应用内对话框；删除先确认。文件信息对话框只保留路径、文件大小与推理方式。
- 内存/显存：设置页常显初始化占用表，按实际设备区分 CUDA、CPU 与主机缓冲，列出模型权重、KV 缓存、计算、输出及其他已上报缓冲。服务合计只显示一次，不与各明细再次相加；不根据 GGUF 文件大小推算显存。未上报、未加载或断连时使用“—”，真实零值保留。数据代表当前已加载模型的初始化分配，保存并重载后更新；不是整个显卡的实时利用率或未保存配置的预测值。
- 测试：上文、拼音和测试按钮，复用真实 InputRequest。修改输入或清空后，旧异步结果不得再出现。测试和历史共用候选结果组件；Rime 候选、排序候选、展示候选、Logprob、逐 Token Logprobs 与边界不匹配放在同一张常显表格中，性能、Token 和分词回退数据直接列于表格下方，无“评分详情”折叠。回退原文必须来自服务，不根据请求上文推算，React 按文本安全渲染。
- 词库：JSON 导入、全量导出、确认清空和分页浏览，保留服务的整数权重规则。读取失败显示重试，禁止把失败显示成空词库。
- 历史：按服务时间戳排序，兼容缺少时间戳的旧记录，request id 不用于排序。窄窗优先显示拼音、排序候选和用时，其他字段在详情中保留。详情保存所选记录快照，轮询不会替换正在查看的记录；打开聚焦顶部，关闭回到对应记录。
- 评测：模型可选已保存模型或“仅 Rime”，并可勾选语料类别、全拼/首拼和多行配置；仅 Rime 忽略配置并按拼音模式去重，模型/配置/模式最多 32 行。语料类别显示文章数、字符数和目标词数。结果表按模型、配置、拼音模式成行，语料成列，每个单元格显示准确率和错误数并可打开分页详情；错误详情保留完整记录并支持单项重测。运行区域只显示当前模型/当前语料的进度、实时词速、预计剩余时间和等待队列，进度条不代表整批总进度。结果由服务按模型文件、有效配置、Rime 快照、语料指纹和算法版本持久化复用，提供刷新语料、清空结果和 JSON 导出。

### 状态与交互

`app/management-context.tsx` 统一读取服务状态和预设、串行执行用户操作。`use-polling-resource` 与 `createRefreshQueue` 合并重叠刷新，每次最多一个读取任务；页面切换、操作和卸载会失效旧响应。评测的成组 IPC 等待全部请求结束后才开始下一轮。状态轮询每3秒一次，页面和可见性变化立即刷新。

设置草稿、模型对话框输入、测试输入、评测选择和展开状态由页面独立保存。历史在窗口生命周期内使用单个 revision 长轮询，通知可主动刷新隐藏页；表格通过稳定 React key 保持焦点。页签切换保留表单状态，并回到页面顶部。

操作反馈使用单条可关闭 toast，成功/普通消息4秒，错误8秒。连接状态显示在页头；页面读取错误保留在相关页面。所有图标按钮提供中文可访问名称，Radix 提供对话框焦点限制、Esc 关闭及键盘操作，关闭后恢复触发元素焦点。减少动态效果的系统偏好会禁用动画。

Tauri 保持 `style-src 'self'`，通过 `index.html` 的 nonce 占位符和 Tauri 资源处理生成每响应 nonce，再交给 `get-nonce`，供 Radix 动态滚动锁样式使用；不启用 `unsafe-inline`。测试服务器模拟同样机制。

## Design tokens 与组件

`src/style.css` 是唯一视觉值入口，使用 shadcn 语义 CSS 变量映射到 Tailwind 4 `@theme`：

- 色彩：background、foreground、card、popover、primary、secondary、muted、accent、destructive、border、input、ring、sidebar、success、warning、overlay。浅色中性底色配绿色强调，深色使用对应语义色。
- 字体：系统中文字体、等宽字体，xs/sm/base/lg/xl/2xl 字号；Tailwind 共享字重与行高尺度。
- 间距：0.25rem 基数，组件只用统一尺度；禁止页面任意像素值。
- 圆角：sm/md/lg/xl；阴影：xs/sm/lg；窗口、弹窗与 toast 尺寸集中定义。
- 组件：shadcn Button、Input、Textarea、NativeSelect、Label、Switch、Checkbox、Card、Badge、Table、Progress、Dialog、AlertDialog。

`components/ui/README.md` 定义允许的变体。Card rows 变体用于紧凑列表，无标题和说明；Button 主操作实色、普通操作描边、图标 ghost；删除确认使用 destructive。分页、空状态、错误状态、确认框与输入结果在业务组件层复用。新增视觉变体必须同步 token 与组件规范。
